How one engagement runs, end to end

A walkthrough of one full engagement — from opening a client record to proving movement ninety days later. Each step shows who runs it, how long it takes, what it produces, and what happens when it does not go to plan. Below the path: the five shapes real engagements take, depending on how far into a transformation you get called in.

Most common route — back to Diagnose, not back to the start. Three others leave step 19.

Why the return loop is short. Client, program and context are built once. From wave two onward only Diagnose → Measure repeats.
Context has two homes. Client context is inherited by every program read-only. Program context is scoped. Any program source can be promoted to client level in one click.
Insivo is not the system of record. Tasks, calendars and documents stay where the client already works. MCP moves evidence in and decisions out.
Insivo runs as an MCP server too. A consultant can query the evidence layer from their own AI tools: which findings moved, where is participation lagging, what did wave two change.

Deeper — engagement shapes

The path always starts at 01. The engagement rarely does.

Every engagement passes through steps 01 to 04 — the client, the program and its context have to exist before anything can be measured. What changes is whether those steps are built from conversations or reconstructed from documents someone else left behind, and where the work the client is paying for actually begins. Five shapes, and each one gives up something the full path takes for granted — usually the baseline.

ShapeWork spansBaseline quality
One product, five shapes. Every shape is a slice of the same 19 steps against the same object model. Nothing here needs a second product — it needs steps 01 to 04 to be cheap when they are reconstruction rather than discovery.
Baseline quality is the real variable. Only the co-start produces a true one. Everything else runs on a reconstructed or absent baseline, and the deliverable has to say so.
The shapes share one model. A diagnostic that later becomes a program keeps its evidence rather than starting over, because both run against the same object chain.
